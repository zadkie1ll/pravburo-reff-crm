# pravburo-reff-crm

Единственная граница агентской платформы с Bitrix24.

Сервис создаёт лиды, повторно читает сделки по входящему webhook, проверяет
`CATEGORY_ID == 2`, извлекает атрибуцию и передаёт команду начисления в
`pravburo-reff-bounty`.

Актуальная карта статусов лида и стадий сделки категории 0 находится в
[`docs/CRM_STAGE_MAP.md`](docs/CRM_STAGE_MAP.md).

## Common submodule

```bash
git clone --recurse-submodules https://github.com/zadkie1ll/pravburo-reff-crm.git
git submodule update --init --recursive
```

Общие контракты берутся из `common`; собственных миграций у CRM нет.

## Маршруты

- `POST /internal/leads` — создаёт лид с именем и телефоном и возвращает
  `{"status": "created", "lead_id": "<Bitrix ID>"}`;
- `GET /internal/clients/search?q=...&page=1` — поиск кандидатов по ФИО
  без записей в Bitrix; сделки всех разрешённых воронок и лиды со ссылками.
  Страница — 50 записей на поток Bitrix плюс все связанные сделки, а не
  строго 50 строк ответа. Контракт, `has_more`, лимиты и ограничения описаны
  в [docs/CLIENT_SEARCH.md](docs/CLIENT_SEARCH.md);
- `GET /internal/deals/{deal_id}/contact-phone`;
- `GET /internal/deals/{deal_id}/existing-client` — предпросмотр существующего клиента
  без создания лида и без записей в Bitrix: сделка, ФИО/телефон контакта, стадия,
  категория, первый платёж в рублях, признак полной оплаты и атрибуция из маркера.
  ID — положительное число длиной до 64 цифр. Отсутствующая сделка или неподходящая
  категория возвращают 404, ошибка Bitrix — 502. Отсутствующие ФИО/телефон — `null`,
  сайт может запросить их вручную;
- `POST /webhooks/bitrix/deal-category`;
- `GET /health/live`, `GET /health/ready`.

Все `/internal/*` требуют `X-Internal-Token`. Webhook Bitrix требует отдельный
`X-Webhook-Secret`.

Для сделок без маркера webhook запрашивает привязку импортированного клиента через
`GET site /internal/existing-clients/deals/{deal_id}` с `X-Internal-Token`.
Ответ 404 означает отсутствие атрибуции; недоступность сервиса или некорректный
ответ возвращают 502 до синхронизации стадии и начислений. Привязанные сделки
проходят обычные правила стадий и выплат. Сделки с маркером сохраняют прежний
путь без дополнительного запроса; конфликты импортированной привязки с устаревшим
маркером должны отклоняться проверками атрибуции на стороне site/bounty.

Аванс партнёру начисляется в воронке «Сопровождение» (категория 2), только если
в поле сделки «Первый платёж» (`UF_CRM_1742468532579`) записано не менее 8 000 ₽.
Поле должно отражать фактическую оплату. Чтобы аванс начислился при заполнении
поля без смены стадии, настройте отправку события `ONCRMDEALUPDATE` на тот же
вебхук. Повторные события не создают второй аванс по той же сделке.

```bash
cp .env.example .env
uv sync
uv run pytest
docker compose up --build -d
```

На production сервис работает в host network и слушает только
`127.0.0.1:8042`.
